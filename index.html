Battle Axe Design Studio
How to Use Studio


1. Start the scenario
Choose the period supplement, table size, base sizes and rules measurement scale. Base size and rules distances are separate: large bases do not force doubled movement.


2. Add historical sources
Upload or paste the scenario material you are working from. Studio keeps source evidence separate from its own suggestions so you can review the interpretation.


3. Build the battlefield
Upload the battlefield map, review detected terrain, correct classifications and manually add anything Studio missed. Approve the battlefield when the important terrain looks right; only approved terrain should drive playtest effects.


4. Review the extraction
Check what Studio thinks the source says. Correct the editable scenario fields rather than treating every automated extraction as authoritative.


5. Build the forces
Organize each side into commands, assign commanders and add Battle Axe unit profiles. Unit names say what the scenario unit is; the profile says which Battle Axe rules it uses.


6. Add scenario rules
Write the rule in plain English, then give it an Engine Interpretation when Studio should enforce it automatically. A scenario rule may explicitly override a Core or supplement rule. The Rules Inspector shows what Studio believes each accepted rule does.


7. Deploy the armies
Create deployment zones and drag units and commanders onto the map. Set facing and check the undeployed indicators before testing.


8. Check the scenario
Use Check Scenario to find missing deployments, overlaps, incomplete engine interpretations and other likely setup problems. Warnings do not prevent deliberate scenario exceptions.


9. Run playtests
Reset the playtest after scenario changes, then run one deterministic game or a batch. Use the replay, action log and heat maps to understand what happened. The automated player chooses among actions the rules engine considers legal; it is not a language model.


10. Use External AI Review
Export the current Studio brief, add your improvement request and paste the AI response back into Studio. Review each proposed change before accepting it. Current-configuration playtest evidence is included so old results do not confuse the review.


11. Publish
Use Scenario Publisher to create the compact finished scenario with historical context, map, force lists, deployment, special rules and victory conditions.


12. Save, reopen or start over
Export the editable Studio project JSON before clearing a project. Open Project restores a saved Studio JSON. New Scenario clears scenario-specific work and starts with a clean workspace.
